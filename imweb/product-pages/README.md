# 상품 상세 라우터 (2026-11-05 다시 씀)

## 왜

아임웹 상품 상세는 모든 상품이 **공용 틀(상품 상세 페이지) 하나**를 쓴다. 크림 상세 코드 위젯을 공용 틀에 두면
새 상품에도 크림 상세가 뜬다. 상품별 '상세 설명' 칸은 영상·버튼·스크립트가 안 된다.

## 구조

```
아임웹 공용 상품 상세 페이지
└─ 코드 위젯: loader.html (한 번 붙이면 끝)
     └─ router.js  (jsDelivr → 안 되면 GitHub 직접, 이 저장소 main, 1분마다 새로)
          ├─ 주소의 idx가 PAGES 목록에 있으면 → pages/<파일>.html을 받아 로더 자리에 넣고 실행
          │    (페이지 파일이 스스로 '상세정보' 본문 맨 앞으로 옮겨 감. 크림은 원래 위젯과 같은 코드)
          └─ 없으면 → 아무것도 안 함 → 아임웹 화면 그대로
```

| 파일 | 하는 일 |
|---|---|
| `loader.html` | 공용 틀의 코드 위젯에 붙이는 것. 라우터를 받아 실행만 한다 |
| `router.js` | 상품 번호 → 상세 파일 목록(`PAGES`). 상품 추가·되돌리기는 여기 한 줄 |
| `pages/nightnight-cream.html` | 나잇나잇 크림(idx 63) 상세. 2026-11-05까지 공용 틀에 붙어 있던 위젯 코드 그대로 |
| `_mock_shop_view.html` | 로컬 확인용 가짜 상품 페이지 (`python3 -m http.server` 후 `/imweb/product-pages/_mock_shop_view.html?idx=63`). 첫 경로를 일부러 막아 예비 경로도 시험한다 |
| `/.github/workflows/purge-jsdelivr.yml` | main 병합 시 jsDelivr 캐시 비우기 |

## 원칙 (2026-11-05 사고 뒤)

그날 로더의 숨김 규칙이 구매평까지 숨겨 라이브에서 구매평이 사라졌다. 그래서:

- **아임웹 요소를 숨기거나 접지 않는다.** 상세 설명·구매평은 아임웹이 그리는 그대로 둔다.
- **목록에 없는 상품에서는 아무것도 하지 않는다.**
- 상품의 '상세 설명' 칸을 비상용으로 쓰지 않는다. 대신 받는 곳을 두 군데(jsDelivr, GitHub)로 둔다.
- 라이브 반영 전 대표가 실제 화면에서 확인한다(이 저장소 작업 환경은 bydose.kr 접속이 막혀 있음).
  새 페이지는 아무 상품 주소에 `&bd_page=파일이름`을 붙여 먼저 본다.

구매평은 아임웹 설정(상세정보 탭 '사용안함')으로 상세 아래에 항상 나온다. 바디 코드 스크립트는 쓰지 않는다.

## 상품 추가

1. 아임웹에서 상품을 만들고 번호(idx)를 확인한다.
2. `pages/<이름>.html`을 만든다(코드 위젯 쓰듯 HTML·CSS·스크립트 자유, 영상·버튼 가능).
   상세정보 본문으로 옮기는 코드는 크림 페이지의 '1. 상세정보 탭 본문으로 옮기기'를 쓴다.
3. main에 병합한 뒤, 아무 상품 주소에 `&bd_page=<이름>`을 붙여 실제 화면에서 본다.
4. `router.js`의 `PAGES`에 `'<idx>': 'pages/<이름>.html'`을 넣고 main 병합.

## 되돌리기

- 한 상품만: `PAGES`에서 그 줄을 지우고 main 병합 → 1분 안에 아임웹 원래 화면.
- 전부: 공용 틀의 코드 위젯에 예전 크림 코드(`pages/nightnight-cream.html` 내용)를 다시 붙인다.

## 점검

크롬 콘솔에서 `document.getElementById('bydose-pages').dataset` →
`bdPage`(받으려는 파일), `bdReady`(넣기 끝), `bdError`(router 또는 page를 못 받음).
